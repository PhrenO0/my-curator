# 🌊 neural-flow — 이상적인 삶 운영 시스템

> 준상(junsang)의 **이상적인 삶 멘토링 + 일정 관리 + 활동 추천** 시스템.
> 매번 거창한 골격만 세우다 *완성*이 안 됐던 이유 — "아이디어 과확장" — 를 시스템 설계 자체에
> 적용해, **하루 단 하나**로 굴러가게 만든 버전.

---

## 핵심 철학 (왜 이렇게 만들었나)

준상의 노션·캘린더에서 직접 읽어낸 축:

- **이상적인 삶 = 지금 이 순간의 "거룩의 상태 = 집중의 상태"를 매일 사는 것.**
  미래 불안이 아니라 현재에 깨어, 하나님과 함께, 내 색깔로 능동적·창의적으로.
- **커리어 North Star:** "AI 그로스 콘텐츠 설계자" — 메시지(미디어) × 시장분석(부동산) × AI 실행력(MS AI School).
- **약점 방어:** 아이디어 과확장 → '기능 다이어트'. 그래서 이 시스템도 **하루 핵심 1개**만 못 박고
  나머지는 백로그로 둔다. 시스템이 사용자의 의지력에 기대지 않게 한다.

---

## 3-레이어 아키텍처

```
🧠 노션 (두뇌)            📆 구글 캘린더 (실행)         🤖 에이전트 (엔진)
─────────────────         ─────────────────────        ─────────────────────
· 비전 종합               · 시간블록                    · 이상적 삶 토론
· 활동 백로그 DB          · 핸드폰 알림                 · 6대 영역 활동 추천
· 상태 관리               · 고정블록(캠프 등)           · 활동 초안 제시
  (제안→승인→예정→완료)                                · 승인분 캘린더 입력
```

- **노션**이 *무엇을/왜* 를 쌓고, **캘린더**가 *언제* 를 실행하고, **에이전트**가 둘을 잇는다.
- 사용자는 **초안 검토 → OK** 만 한다. 빈 칸을 손으로 채우지 않는다.

## 활동 백로그 DB

노션 허브 페이지(`config.json > notion.hub_url`) 아래의 `🗃️ 활동 백로그`.

**속성:** 활동명 · 영역 · 세부분류 · 상태 · 우선순위 · 에너지 · 반복 · 예상시간(분) · 일정 · 왜(비전연결)

**상태 흐름:** `제안됨` → `승인됨` → `예정됨`(캘린더 등록됨) → `진행중` → `완료` (`보류`)

**에너지(준상의 알파/베타파 개념):** `딥워크(베타파)` / `가벼움(알파파)` / `루틴`

**뷰:** 📅 캘린더(일정 기준) · 🗂️ 상태 보드(상태 기준)

## 운영 루프

### 주간 (일요일 저녁 또는 월요일 아침, ~15분)
1. **토론** — 이상적인 삶·이번 시즌 우선순위 점검 (에이전트가 질문)
2. **추천** — 에이전트가 6대 영역에서 이번 주 활동을 `제안됨`으로 DB에 추가
3. **초안** — 캠프·마감 등 고정일정 사이에 시간블록 초안 제시
4. **승인** — 고른 것만 캘린더로 (`상태 → 예정됨`)
5. **회고** — 지난주 실행률 → 다음주 추천 보정

### 일간 (아침 1분)
- **오늘의 단 하나**: 허브 페이지 상단에서 오늘 반드시 끝낼 1개 확인.
- 끝나면 `완료` 체크. 그게 전부다.

## 재실행 방법 (이게 "완성"의 핵심)

이 시스템은 **코드가 아니라 프롬프트 + 노션/캘린더 데이터**로 굴러간다. 셋 중 편한 걸로:

1. **Claude Code / Claude 데스크톱 (MCP 연결)** — 가장 강력.
   `prompts/mentor-prompt.md` 를 붙여넣고 "이번 주 추천 돌려줘" 라고 하면
   에이전트가 노션·캘린더를 직접 읽고 추천→초안→(승인 시)입력까지 한다.

2. **아침 브리핑** — `prompts/daily-brief-prompt.md` 를 매일 아침 실행.
   '오늘의 단 하나 + 어제 리뷰 + 마감 임박 + 영성/트렌드 1개'.

3. **헤르메스(텔레그램) cron** — 준상이 이미 쓰는 지속 에이전트가 자동화의 최적지.
   `AUTOMATION.md` 의 cron 레시피 참고.

> 핵심 ID(노션 페이지/DB/뷰, 캘린더)는 모두 `config.json` 에 있다.
> 에이전트는 항상 거기서 위치를 읽는다.

## 파일 구조

```
neural-flow/
├── README.md                      ← 이 문서 (운영 매뉴얼)
├── ARCHITECTURE.md                ← 에이전트 루프 교육 ("어떤 파이프라인을 만들까")
├── SETUP.md                       ← 에이전트 켜기 (시크릿/Actions, 5분)
├── config.json                    ← 노션/캘린더 ID·영역 정의
├── AUTOMATION.md                  ← 자동화 옵션 + 한계
├── agent.py                       ← ★ 멘토링 에이전트 본체 (SENSE→THINK→ACT)
├── state.json                     ← 에이전트의 장기 기억 (비전·9영역·활동)
├── brief_email.py                 ← 브리핑 HTML 이메일 렌더링
├── notion_sync.py                 ← (선택) Notion 라이브 읽기/기록
├── tg.py                          ← (선택) 텔레그램 푸시 (아침 단 하나·저녁 체크인)
├── gmail_sensor.py                ← (선택) Gmail 마감 센서
├── radar.py                       ← ★ 기회·정보 레이더 (네이버+Threads → Gemini 큐레이션)
├── threads_source.py              ← (선택) Threads 공식 keyword_search (기술·DB 근원)
├── coverletter.py                 ← ★ 멀티에이전트 RAG 자소서 엔진 (검색→3초안→통합→AI티 검열)
├── experiences.json               ← 경험 자산 DB (RAG 검색 재료, 키워드 태깅)
├── master.json                    ← 마스터 자소서 6문항 (엔진이 '기본 뼈대'로 변주)
├── job_input.example.json         ← 자소서 엔진 입력 템플릿 (→ job_input.json 복사해 사용)
├── prompts/
│   ├── mentor-prompt.md           ← 멘토링·추천 에이전트 프롬프트 (재사용)
│   ├── daily-brief-prompt.md      ← 아침 브리핑 프롬프트
│   ├── cover-letter-customizer.md ← 자소서 커스터마이저 프롬프트 + 엔진 사용법
│   ├── decision-journal.md        ← 결정 일지 Pre-mortem 프롬프트(과확장 처방)
│   └── hermes-tracking.md         ← 헤르메스 양방향 추적 스킬/cron
└── workflows/
    └── weekly-recommend.workflow.js  ← (선택) 주간 추천 워크플로우 스크립트

.github/workflows/neural-flow.yml  ← 데일리·위클리 cron (curator 와 동일 구조)
```

> 🤖 **에이전트 파이프라인:** `agent.py` 는 준상의 `curator_bot.py` 와 똑같은
> 구조(Python → Gemini → 이메일)다. 이미 있는 시크릿만으로 매일 07:00 브리핑이 온다.
> 구조를 배우려면 `ARCHITECTURE.md`, 켜려면 `SETUP.md`.
