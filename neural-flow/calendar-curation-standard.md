# 캘린더 큐레이션 표준

> 세션에서 캘린더 이벤트를 만들거나 정리할 때 매번 따르는 표준. 사용자가 "시간관리 에이전트" 역할을 요청(2026-07-22)해서 문서화.

## 색상 매핑 (colorId)
| 색 | colorId | 카테고리 |
|---|---|---|
| 🔴 Tomato | 11 | 커리어·마감·결과발표 |
| 🔵 Blueberry | 9 | 콘텐츠·영상팀·팟캐스트 |
| 🟢 Basil | 10 | 빌드·창업·해커톤·BD |
| 🟡 Banana | 5 | 학업·성장·교육(강의·아카데미) |
| 🟣 Grape | 3 | 영성·교회 |
| ⚪ Graphite | 8 | 개인·일상·이동 |

## 이벤트 생성/수정 시 규칙
1. **색은 항상 채운다.** 기본색(무색) 방치 금지.
2. **설명(description)에 최소 포함**: 무엇인지(내용) · 왜 이 시간대인지(선행/후행 일정과의 관계) · 불확실한 정보는 ⚠️로 명시.
3. **본인 일정이 아닌 정보성 이벤트**(예: 공유 캘린더 동기화된 남의 일정)는 큐레이션 대상에서 제외 — 색·설명 건드리지 않는다.
4. **이동시간은 별도 이벤트로 명시.** 추정치일 경우 반드시 "⚠️예상, 실시간 내비 확인 필요"로 표시. 왕복이 필요하면 양쪽 다 만든다.
5. **새 일정 추가 시 인접 이벤트와 충돌 체크.** 충돌 발견 시 사용자에게 묻지 말고 먼저 합리적으로 재배치한 뒤, 근거를 설명에 남기고 보고한다(과도한 질문보다 판단 우선, 단 정보가 진짜 없으면 질문).
6. **큰 작업(수 시간~수십 시간)은 여러 세션으로 분할**하고 제목에 `(n/총n)` 표기. 한 주에 다 못 들어가면 정직하게 이월 제안(무리한 압축 금지).
7. **마감과 "작업 착수/마무리" 이벤트를 구분.** 마감은 🔴, 작업 세션은 해당 카테고리 색.

## 알려진 한계
- 이 표준은 **세션 내 수동 큐레이션 기준**이다. `neural-flow/agent.py`(cron 자동화)는 현재 Google Calendar API 접근 권한이 없어 — Notion·Gmail만 자동 조회. 캘린더 자동 점검을 완전히 자동화하려면 별도로 Calendar API 인증을 cron 워크플로우에 추가해야 함(미착수).
