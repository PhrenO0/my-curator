# 🏗️ neural-flow 아키텍처 — "어떤 에이전트를 만들어야 하나"

> 준상이 *직접 배우고 확장*하기 위한 문서. 멘토링 에이전트는 결국
> **"기억 → 추론 → 행동 → 다시 기억"** 네 부품의 반복이다. 그게 전부다.

---

## 1. 에이전트 루프 (모든 자율 에이전트의 골격)

```
        ┌──────────────────────────────────────────────┐
        │                                              │
        ▼                                              │
   ┌─────────┐   ┌─────────┐   ┌─────────┐   ┌──────────────┐
   │ SENSE   │──▶│ THINK   │──▶│ ACT     │──▶│ REMEMBER     │
   │ 상태읽기 │   │ LLM추론 │   │ 실행    │   │ 기록·보정    │
   └─────────┘   └─────────┘   └─────────┘   └──────────────┘
   state.json    Gemini        email/Notion   완료·회고
   Notion/Cal    +mentor       /calendar      → 다음 추천
```

이 repo의 매핑:

| 단계 | 하는 일 | 파일 |
|------|---------|------|
| **SENSE** | 비전·9개 영역·활동·마감을 읽는다 | `state.json`, `notion_sync.pull_live_activities` |
| **THINK** | 비전에서 역산해 '오늘의 단 하나'+코칭 생성 | `agent.think()` → Gemini |
| **ACT** | 이메일 발송, Notion에 기록 | `brief_email.render`, `notion_sync.log_one_thing` |
| **REMEMBER** | 완료/회고가 다음 추천을 바꾼다 | `weekly` 모드 + 활동 상태 |

> 준상의 `curator_bot.py` 와 **정확히 같은 골격**이다. 큐레이터는 SENSE=뉴스스크랩,
> THINK=master_curate, ACT=이메일. neural-flow 는 대상이 '뉴스'가 아니라 '너의 삶'일 뿐.

## 2. 4개 부품을 고를 때의 선택지

에이전트를 만들 때 매번 이 4개를 고르면 된다:

### ① 기억 (State / Memory) — *가장 중요*
에이전트는 기억이 없으면 매번 처음부터다. 선택지:
- **파일** (`state.json`) — 가장 간단, 버전관리됨. ← 지금 이걸로 시작
- **Notion DB** — 사람이 보고 고치기 좋음, 라이브. ← `NOTION_TOKEN` 붙이면 활성
- 벡터DB/SQLite — 기억이 수백 개로 커지면

### ② 추론 (Reasoning) — LLM + 역할 프롬프트
- 모델: Gemini(이미 키 보유) / Claude / GPT
- 핵심은 모델이 아니라 **system 프롬프트**(= `prompts/mentor-prompt.md`).
  "너는 누구고, 무엇을 알고, 무엇을 줄이고, 무엇을 출력하라"를 박아둔다.

### ③ 행동 (Action / Channels) — 어디로 내보낼까
- **이메일**(이미 보유) · **Notion 기록** · **캘린더 입력** · 텔레그램(헤르메스)
- 행동은 항상 **승인 게이트**를 둘지 정한다. 캘린더 시간 점유 = 승인 후, 기록/제안 = 자동 OK.

### ④ 트리거 (Cadence) — 언제 깨어날까
- **GitHub Actions cron** (지속·무료) ← 이걸로 매일 07:00 / 일요일 20:00
- 헤르메스 텔레그램 cron (대화형)
- 수동(Claude+MCP 세션) — 깊은 토론·주간 설계용

## 3. 너에게 권하는 파이프라인 (단계별)

> 한 번에 다 만들지 마라(과확장!). 아래 순서로 *작동하는 것부터*.

**Lv.0 — 이미 됨**: 캘린더 반복 알림(QT·회개). 코드 0.

**Lv.1 — 지금 이 repo** ✅: `state.json` → Gemini → 이메일.
`GOOGLE_API_KEY`/`SENDER_EMAIL`/`SENDER_PASSWORD` 만으로 매일 07:00 브리핑.
새 시크릿 0개. → `SETUP.md` 보고 워크플로 켜기만 하면 끝.

**Lv.2 — Notion 라이브 연결**: `NOTION_TOKEN` 추가 →
에이전트가 활동 DB 를 실시간으로 읽고, 허브에 '오늘의 단 하나'를 기록.

**Lv.3 — 캘린더 쓰기**: Google Calendar API 자격증명 추가 →
주간 모드가 추천 활동을 실제 시간블록 초안으로 만들고, 승인분만 입력.
(MVP에선 이 단계는 Claude+MCP 세션이 대신한다 — 무설정.)

**Lv.4 — 양방향 대화**: 헤르메스 텔레그램에 연결 →
"오늘 그거 했어?" 같은 능동 추적. 진짜 '철저한 관리'의 완성형.

## 4. 확장하는 법 (직접 해보기)

- **새 센서 추가**: `agent.load_state()` 에 소스를 하나 더 합쳐라
  (예: Gmail 에서 '마감·면접' 메일 → 마감 카운트다운에 자동 반영).
- **새 행동 추가**: `agent.run()` 끝에 `maybe_*` 함수를 하나 더.
- **새 영역 추가**: `state.json > domains` 에 항목 추가 → 프롬프트가 자동 반영.
- **추론 강화**: `weekly` 모드처럼, 어려운 판단은 LLM 여러 번 호출(생성→검증)로.

> 기억하라: 시스템이 너의 의지력을 대신하게 하는 게 목표다.
> 매일 네가 하는 일은 이메일 한 통 읽고 **'단 하나'에 OK** 하는 것뿐.
