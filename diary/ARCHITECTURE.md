# 🕯️ diary-prep — "일기를 쓰기 전에, 책상을 차려두는 에이전트"

> 목적: 준상이 **키워드 하나 또는 영감 한 줄**을 던지면,
> 에이전트가 그 주제를 **더 깊이 파고**, **어울리는 음악을 모으고**,
> **전문가의 감각 어휘**로 책상을 차려둔다.
> 준상이 하는 일은 차려진 책상 앞에 앉아 **쓰는 것**뿐이다.

`neural-flow/ARCHITECTURE.md`의 4부품(기억·추론·행동·트리거)을 그대로 따른다.
다른 점은 대상이 '뉴스'도 '삶'도 아닌 **오늘의 한 감정/한 주제**라는 것.

---

## 1. 파이프라인

```
  씨앗            심화              감각              사운드           차림
┌────────┐   ┌──────────┐   ┌────────────┐   ┌───────────┐   ┌──────────┐
│ SEED   │──▶│ EXPAND   │──▶│ RESONATE   │──▶│ SCORE     │──▶│ COMPOSE  │
│ 키워드  │   │ 지식 심화 │   │ 전문가 감각 │   │ 배경음악   │   │ 준비지 생성│
└────────┘   └──────────┘   └────────────┘   └───────────┘   └──────────┘
   CLI /       LLM 축 분해     lexicon/         YouTube        prep/*.md
   inbox.md    + 검색 3소스    + 인용(출처)      (+Spotify)     + 일기 링크
                    │                                              │
                    └──────────── REMEMBER: diary/.state/ ─────────┘
                            (쓴 키워드·튼 곡·쓴 어휘를 기억해 반복을 피함)
```

| 단계 | 하는 일 | 산출 |
|------|---------|------|
| **SEED** | 키워드/영감 한 줄을 받는다 | `seed` 문자열 |
| **EXPAND** | 주제를 4개 축으로 쪼개고 각 축마다 자료를 모은다 | 링크 + 요약 |
| **RESONATE** | 그 주제의 온도·질감·색을 전문가 어휘로 고른다 | 감각 팔레트 + 인용 |
| **SCORE** | 그 팔레트에 맞는 곡을 고른다 | 3~5곡 + 이유 |
| **COMPOSE** | 한 장짜리 준비지를 만들고 오늘 일기에 링크 | `prep/…-prep.md` |
| **REMEMBER** | 쓴 것들을 기록해 다음엔 다른 각도로 | `.state/*.json` |

---

## 2. 단계별 설계

### ① SEED — 씨앗 받기

세 가지 입구. 전부 같은 함수로 들어간다.

```bash
./diary/prep.sh "번아웃"                    # 키워드
./diary/prep.sh "오늘 지하철에서 본 노인의 손"  # 영감 한 줄
./diary/prep.sh                              # inbox.md 맨 아래 줄을 씨앗으로
```

`diary/inbox.md`는 하루 중 떠오른 조각을 아무렇게나 던져두는 파일이다.
씨앗은 **명사 하나여도 되고 문장이어도 된다** — EXPAND가 알아서 축을 잡는다.

### ② EXPAND — 깊이 파기

씨앗 하나를 그대로 검색하면 위키 수준의 표면만 나온다.
그래서 **LLM이 먼저 4개의 축으로 쪼개고**, 축마다 따로 검색한다.

| 축 | 질문 | 검색 소스 |
|----|------|-----------|
| **개념** | 이 말은 정확히 무엇인가, 어원은 | Wikipedia + Naver 백과 |
| **맥락** | 지금 이 주제가 왜 회자되나 | Naver 뉴스 (`get_naver_news`) |
| **반대편** | 이 주제를 반박·의심하는 시선은 | LLM 질의 + 뉴스 |
| **사람** | 이걸 평생 붙들고 산 사람은 누구인가 | YouTube 강연·다큐 (`get_youtube_videos`) |

> **'반대편' 축이 이 설계의 핵심이다.** 일기가 자기확인으로 끝나지 않게 하는 장치.
> 준상의 약점(아이디어 과확장)을 거르는 `decision-journal.md`의 Pre-mortem과 같은 역할.

검색 함수는 `curator_bot.py`의 것을 **그대로 import해서 재사용**한다. 새 키 0개.

### ③ RESONATE — 전문가의 감각 빌려오기

요청의 핵심인 "전문가들의 감각적인 느낌"을 두 층으로 나눠 구현한다.

**(a) 감각 어휘 사전 — `diary/lexicon/*.md`**

분야별 전문가들이 감각을 서술할 때 쓰는 **어휘 팔레트**를 미리 담아둔다.
LLM은 여기서 오늘 주제에 맞는 8~12개를 골라 제시한다.

```
diary/lexicon/
├── music.md          # 음악비평 — 여백, 잔향, 어택, 미니멀, 러프한 질감
├── art.md            # 미술비평 — 마티에르, 채도, 여백, 붓자국, 임파스토
├── scent.md          # 조향 — 탑/미들/베이스, 드라이다운, 시프레, 우디
├── cinema.md         # 촬영 — 역광, 얕은 심도, 핸드헬드, 색온도, 롱테이크
├── architecture.md   # 건축 — 동선, 물성, 스케일, 빛의 우물, 켜
└── literature.md     # 문학 — 문체의 온도, 만연체, 시점, 여운, 절제
```

어휘는 **누구의 문장도 아니다** — 그 분야의 공용 술어다. 마음껏 쓴다.

**(b) 전문가의 문장 — 짧은 인용 + 출처 명기**

주제에 맞는 실제 전문가/작가의 문장을 **2~3개, 각 1~2문장으로 짧게** 가져오고
**반드시 출처(사람·출처명·링크)를 붙인다.** 준비지에서도 `> 인용` 블록으로
준상 본인의 글과 시각적으로 분리한다.

> ⚠️ **설계상의 선 긋기**: 남의 문장을 길게 퍼오면 그건 일기가 아니라 스크랩이다.
> 인용은 **불씨용으로 짧게**, 감각 어휘는 **재료로 마음껏**. 이 경계를 프롬프트에 박아둔다.
> 준상이 쓸 문장은 어디까지나 준상의 것이어야 한다.

### ④ SCORE — 배경음악 모으기

**음악 파일은 받지 않는다. 링크와 맥락만 모은다.** (저작권 + 저장소 용량)

씨앗 → 무드 벡터 → 검색어 순으로 내려간다.

```
씨앗 "번아웃"
  └─ LLM이 무드 벡터로 번역
       { energy: 낮음, valence: 중립~어두움, tempo: 60~80,
         texture: "잔향 많고 저역이 두꺼운", 
         레퍼런스: ["Nils Frahm 계열 modern classical",
                    "ECM 레이블 특유의 여백", "앰비언트 드론"] }
  └─ 레퍼런스마다 YouTube 검색 → 곡당 "왜 어울리는지" 한 줄 생성
```

무드 → 장르 매핑은 `diary/lexicon/music.md`에 **표로 명시**해 둔다.
LLM이 매번 새로 지어내지 않고 이 표를 참조하게 한다 (재현성).

- **Lv.1 (지금 가능)**: YouTube Data API — 이미 `YOUTUBE_API_KEY` 보유. 새 키 0개.
- **Lv.2 (선택)**: Spotify Client Credentials — 무료 발급, `audio_features`로
  tempo/energy/valence를 **실제 수치로 필터**할 수 있어 정확도가 확 올라간다.
- 여러 곡을 한 번에 듣는 링크는 API 없이 URL로 만든다:
  `https://www.youtube.com/watch_videos?video_ids=ID1,ID2,ID3`

### ⑤ COMPOSE — 준비지 한 장

```
diary/prep/2026/08/2026-08-28-prep.md
```

그리고 오늘 일기(`2026-08-28.md`) 맨 위에 준비지 링크 한 줄을 꽂아준다.
**일기 본문은 절대 건드리지 않는다** — 에이전트는 책상만 차리고 물러난다.

준비지 구성:

```markdown
# 🕯️ 2026-08-28 준비지 — "번아웃"

## 1. 씨앗
한 줄 정의 + 왜 오늘 이게 떠올랐을지에 대한 추측 한 줄

## 2. 깊이
### 개념  / ### 맥락  / ### 반대편  / ### 사람
축마다 3~4줄 + 출처 링크

## 3. 전문가의 문장
> 인용 (— 이름, 출처, 링크)   ×2~3

## 4. 감각 팔레트
어휘 10개 · 색 · 온도 · 질감

## 5. 오늘의 사운드트랙
곡 3~5개 · 각 곡 "왜 어울리나" 한 줄 · 이어듣기 링크

## 6. 펜을 여는 질문
답이 정해지지 않은 질문 3개

## 7. 더 읽을거리
링크 목록
```

### ⑥ REMEMBER — 반복 피하기

`curator_bot.py`의 `history.json` 패턴을 그대로 쓴다.

```
diary/.state/
├── seeds.json     # 언제 무슨 키워드를 팠나 → "지난달에 판 주제다, 다른 축으로"
├── music.json     # 튼 곡 ID → 같은 곡 재추천 금지
└── quotes.json    # 쓴 인용 → 중복 방지
```

## 3. 파일 배치

```
diary/
├── README.md              # 사용법 (기존)
├── ARCHITECTURE.md        # 이 문서
├── TEMPLATE.md            # 일기 템플릿 (기존)
├── new.sh                 # 빈 일기 생성 (기존)
├── prep.sh                # ← 준비지 생성 진입점 (신규)
├── inbox.md               # ← 떠오른 조각 던져두는 곳 (신규)
├── lexicon/*.md           # ← 감각 어휘 사전 (신규, 사람이 계속 키움)
├── prep/YYYY/MM/*-prep.md # ← 생성된 준비지
├── .state/*.json          # ← 기억
└── YYYY/MM/YYYY-MM-DD.md  # 일기 본문

neural-flow/
├── diary_prep.py          # ← 로직 (신규)
└── prompts/diary-prep.md  # ← 역할 프롬프트 (신규)
```

**로직을 `neural-flow/`에 두는 이유**: 이 저장소는 이미
`prompts/*.md`(역할) + `*.py`(실행) + `state.json`(기억)으로 나뉘어 있다.
`diary/`는 **내 글과 내 재료**만, `neural-flow/`는 **에이전트의 뇌**만 담는 규칙을 지킨다.

## 4. LLM 호출 설계

한 번에 다 시키면 각 파트가 얕아진다. **3번 나눠 부른다.**

| # | 역할 | 입력 | 출력 | temp |
|---|------|------|------|------|
| 1 | **분해** | 씨앗 | 4개 축의 검색 질의 + 무드 벡터 | 0.3 |
| 2 | **종합** | 검색 결과 원문 | 깊이 4개 축 + 질문 3개 | 0.4 |
| 3 | **감각** | 씨앗 + lexicon + 곡 목록 | 팔레트 + 곡별 이유 | 0.8 |

3번만 temperature를 높이는 게 포인트 — **사실은 차갑게, 감각은 뜨겁게.**
모델은 기존 `get_llm()`을 그대로 쓴다 (Gemini/OpenAI/Azure 자동 선택).

## 5. 트리거

일기는 마음이 동할 때 쓰는 것이므로 **수동이 기본**이다.

- **기본**: `./diary/prep.sh "키워드"` — 즉시 실행, 1~2분
- **선택**: GitHub Actions cron으로 매일 저녁 `inbox.md`에 쌓인 씨앗을 자동 준비
  (`.github/workflows/`에 `diary-prep.yml` 추가 — 기존 두 워크플로와 같은 형태)

> cron은 **inbox에 씨앗이 있을 때만** 돈다. 없으면 조용히 종료.
> 매일 억지로 준비지를 만들면 일기가 숙제가 된다.

## 6. 구현 순서 (한 번에 다 만들지 않는다)

| 단계 | 범위 | 새 키 | 상태 |
|------|------|-------|------|
| **Lv.0** | `diary/` 폴더·템플릿·`new.sh` | 0 | ✅ 완료 |
| **Lv.1** | `prep.sh` + `diary_prep.py` — 씨앗→깊이→팔레트→YouTube 3곡→준비지 | **0** | 다음 |
| **Lv.2** | `lexicon/` 6종 채우기 + 인용 출처 검증 | 0 | |
| **Lv.3** | Spotify `audio_features`로 곡 정확도 개선 | Spotify ×1 | |
| **Lv.4** | cron 자동 준비 + Notion 결정일지/활동DB 연동 | 0 | |

**Lv.1은 기존 키(GOOGLE_API_KEY, YOUTUBE_API_KEY, NAVER_*)만으로 전부 동작한다.**

---

## 7. 이 설계가 지키려는 원칙

1. **에이전트는 재료만 놓는다.** 일기 본문은 절대 대신 쓰지 않는다.
2. **인용은 짧게, 어휘는 마음껏.** 전문가의 감각은 빌리되 문장은 훔치지 않는다.
3. **음악은 링크로.** 파일을 받지 않는다.
4. **반대편 축은 필수.** 일기가 자기확인으로 끝나지 않게.
5. **없으면 조용히 넘어간다.** 키가 없거나 검색이 비면 그 섹션만 빠진다 — 전체가 죽지 않는다.
