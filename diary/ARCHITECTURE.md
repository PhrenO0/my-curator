# 🕯️ diary-prep — 감각적인 글을 쓰기 위한 리서치 에이전트

> **일기를 대신 쓰는 도구가 아니다. 일기를 쓰기 전에 재료를 채집하는 도구다.**
>
> 준상이 키워드 하나, 혹은 어디서 주워온 문장 하나를 던지면 —
> 그 **원본을 끝까지 추적하고**, 사전적 정의와 어원을 캐고,
> 그 자리를 먼저 밟은 시·칼럼·에세이를 모아,
> **인용할 만한 문장 몇 개를 골라 내민다.**

출력 형식의 기준 — 둘 다 실제 웹 수집으로 만든 표본이다:
- **[prep/EXAMPLE.md](prep/EXAMPLE.md)** — **문장형** 씨앗 (원전 추적 중심)
- **[prep/EXAMPLE-word.md](prep/EXAMPLE-word.md)** — **단어형** 씨앗 (정의·어원 중심)

---

## 1. 왜 방향을 다시 잡았나

첫 설계는 씨앗을 `개념 / 맥락 / 반대편 / 사람` 네 축으로 쪼갰다.
그건 **뉴스 큐레이션의 골격**이었다 — 이 저장소의 `curator_bot.py`가 하는 일.
"오늘 알아야 할 정보"를 모으는 데는 맞지만, **감각적인 글을 쓰는 데는 쓸모가 적다.**

감각적인 글에 필요한 건 정보가 아니라 **언어**다. 그래서 축을 전부 바꾼다.

| | 이전 (정보 수집) | 지금 (문장 채집) |
|---|---|---|
| 묻는 것 | 이 주제에서 뭘 알아야 하나 | 이 말을 **누가 처음 했고**, 어떻게 썼나 |
| 모으는 것 | 뉴스·영상 요약 | **원문 · 정의 · 시구 · 인용** |
| 결과물 | 브리핑 | **인용할 수 있는 문장 목록** |
| 성공 기준 | 놓친 게 없다 | **오늘 한 문장을 빌려 쓸 수 있다** |

---

## 2. 두 개의 모드

```
[RESEARCH]  키워드/문장  ──▶  채집  ──▶  준비지  ──▶  (준상이 읽고 쓴다)
                                                              │
[ARCHIVE]   원문 입력  ◀───────────────────────────────────────┘
                 └──▶  Notion 「일기」 DB 에 정리해 적재
```

- **RESEARCH** — 쓰기 **전**. 재료를 차린다.
- **ARCHIVE** — 쓰기 **후**. 준상이 쓴 원문을 받아 Notion에 형식 맞춰 넣는다.

두 모드는 독립적이다. 리서치 없이 쓴 글도 ARCHIVE로 들어갈 수 있다.

---

## 3. RESEARCH — 다섯 개의 층

씨앗은 두 종류다. 층의 무게가 달라진다.

- **단어형** — `순수함`, `번아웃`, `다정함` → ①②③⑤ 가 두꺼워진다
- **문장형** — `"별을 보려면 어두운 곳으로 가라" — 궤도` → **④가 최우선**

### ① 정의와 어원 — *가장 저평가된 층*

표준국어대사전·우리말샘·한자·유의어. 특히 **유의어 사이의 미세한 차이**.

> `순수` / `순결` / `결백` / `천진` — 넷 다 다른 말이다.
> 이 차이를 알고 쓴 문장과 모르고 쓴 문장은 완전히 다르다.

감각적인 글은 **정확한 단어를 고르는 데서** 나온다. 형용사를 더 얹는 게 아니라.

### ② 사실의 뼈대

그 말 밑에 깔린 **실제 원리**. 과학·역사·어원 무엇이든.

> 궤도의 문장이 강한 이유는 시적이어서가 아니라 **암순응이 진짜이기 때문**이다.
> 뼈대를 알면 남의 은유를 베끼지 않고 **내 은유를 새로 지을 수 있다.**
> (예시에서 원문보다 좋은 재료 '주변시'가 여기서 나왔다.)

### ③ 곁에 둘 문장 — 시 · 칼럼 · 에세이

같은 자리를 먼저 밟은 사람들. 시 → 칼럼 → 블로그·브런치 순으로 신뢰도를 매긴다.
**베끼려고가 아니라 내 각도를 찾으려고** 읽는다.

### ④ 원전 추적 (provenance) — *이 설계의 심장*

떠도는 문장은 대개 3차 가공물이고, **가공되면서 뭉개진다.**

| 등급 | 무엇 | 예 |
|------|------|-----|
| **1차** | 본인의 입/손 | 강연 영상·책 본문·인터뷰 원본 |
| **2차** | 받아적은 기록 | 신문 기사, 강연 후기 |
| **3차** | 카드뉴스·짤·SNS | Threads/인스타 인용 카드 ← 보통 여기서 처음 만난다 |

**규칙:**
1. 3차에서 멈추지 않는다. 2차 이상을 못 찾으면 **"미확인"이라고 명시**한다.
2. 원문과 유통본이 다르면 **둘 다 보여주고 차이를 짚는다.**
3. 출처 없는 문장은 **"출처 미상"으로 표기**한다. 그럴듯한 이름을 붙이지 않는다.

> 잘못된 출처를 단 인용은 글 전체의 신뢰를 무너뜨린다.
> **모르면 모른다고 쓰는 게 이 층의 성능이다.**

### ⑤ 감각 팔레트 + 사운드트랙

`lexicon/`의 분야별 술어에서 오늘 주제에 맞는 8~12개 + 색·온도·질감.
음악은 **링크만** 모은다 (`lexicon/music.md`의 무드→장르 매핑표 참조).
이 층은 ①~④가 채워진 뒤의 마감재다.

### ⑥ 지난 글과의 연결 — *마지막 층이자 착지점*

`.state/seeds.json`과 Notion 「일기」 DB를 뒤져 **준상이 이미 쓴 글** 중
이 씨앗과 닿는 것을 찾아 붙인다.

> 「순수함」 채집에서 이 층이 가장 큰 걸 물어왔다. 준상은 그 글에서
> *"안락함, 중독, 관성을 **버려내야** 한다"* 고 썼는데, 그건 어원상
> **粹(깎아내어 얻는 순수)** 였다. 어원을 몰랐을 뿐 방향은 정확했다.
> 리서치가 그때 쓴 문장의 **뒷받침**이 된 것이다.

**리서치가 바깥에서 온 재료로만 끝나면 남의 글이 된다.**
이 층이 있어야 채집물이 준상의 글로 착지한다. 그래서 마지막에 둔다.

## 4. 출력 — 인용 카드

준비지의 모든 인용은 이 형태를 지킨다. **출처 없는 문장은 실리지 않는다.**

```markdown
> 인용문 (2~3행을 넘기지 않는다)
> — 말한 이, 자리/출처, [링크](url)  · 등급: 1차
```

준비지 전체 구성은 [prep/EXAMPLE.md](prep/EXAMPLE.md)를 그대로 따른다:
`원전 추적 → 사실의 뼈대 → 곁에 둘 문장 → 감각 팔레트 → 사운드트랙 → 펜을 여는 질문`

## 5. ARCHIVE — Notion 적재

**대상**: 🌠 일기 페이지 → 「일기」 DB
`https://app.notion.com/p/01d739cee8d144428ad9c98226b63ff9`
(data source `collection://30bb9019-0357-81b9-9462-000b8099957a`)

**스키마**: `이름`(title) · `날짜`(date) · `요일`(formula, 자동) · `일기장`(relation) · `하트`(checkbox)

**기존 글에서 읽어낸 형식** (「순수함」, 「흔들리지 않는 다정함」):
- 제목 = **키워드 한 개 또는 짧은 구절**. 문장이 아니다.
- 본문 = 짧은 행으로 끊어 쓴 잠언체. 마침표로 호흡을 끊는다.
- 끝맺음 = **자신에게 건네는 명령형** ("그저 다정하라", "숨을 쉬어라")

**적재 규칙:**
1. **원문의 문장을 고쳐 쓰지 않는다.** 행 나눔·오탈자·문단만 정리한다.
2. 제목이 없으면 본문에서 **키워드 한 개를 뽑아 제안하되, 확정은 준상이 한다.**
3. 리서치 준비지를 참고했다면 맨 아래 **출처 각주**로만 남긴다.
4. `날짜`는 쓴 날. `일기장` relation은 기존 값을 따라간다.

## 6. 수집 경로

| 층 | 소스 | 접근 | 키 |
|----|------|------|-----|
| ① 정의·어원 | 표준국어대사전·우리말샘 | Open API | 무료 발급 1개 |
| ① 유의어 차이 | 네이버 백과 | `curator_bot.get_naver_news` 계열 | **보유** |
| ② 사실의 뼈대 | 위키백과·나무위키 | Wikipedia API / 크롬 | 0 |
| ③ 문장 | 브런치·칼럼·블로그 | Naver 블로그 API + 크롬 | **보유** |
| ④ 원전 추적 | 전 웹 | **웹 검색 + 크롬 본문 확인** | ↓ |
| ⑤ 음악 | YouTube | YouTube Data API | **보유** |

**④가 유일하게 새 수단을 요구한다.** 전 웹을 훑어야 하므로:
- **Claude 세션(트랙 A)에서는 내장 웹 검색으로 지금 즉시 가능** — EXAMPLE.md가 그 증거
- **스크립트(트랙 B)에서는** Google Programmable Search API(무료 100건/일) 또는
  **Playwright + Chrome**으로 검색·본문 수집. 크롬은 JS 렌더링이 필요한
  Threads·브런치 같은 곳에서 특히 필요하다.

## 7. 두 개의 실행 트랙

**트랙 A — Claude 세션 (지금 당장, 코드 0줄)**
준상이 대화창에 키워드나 문장을 던지면 Claude가 직접 웹 검색으로 5개 층을 채우고
준비지를 만든 뒤, ARCHIVE 모드로 Notion에 적재한다.
→ **품질이 가장 높다.** 원전 추적처럼 판단이 필요한 일은 사람 손에 가까울수록 낫다.

**트랙 B — 스크립트 + cron (자동화)**
`inbox.md`에 쌓인 씨앗을 저녁에 자동으로 준비지로 만든다.
→ **트랙 A로 형식이 굳은 다음에 만든다.** 형식이 흔들리는 동안 자동화하면 쓰레기가 쌓인다.

> 이 저장소의 약점은 **아이디어 과확장**이다(`neural-flow/prompts/decision-journal.md`).
> 트랙 A로 열 번쯤 써 보고, 그때도 귀찮으면 그때 트랙 B를 만든다.

## 10. 원칙

1. **에이전트는 재료만 놓는다.** 일기 본문은 준상이 쓴다. ARCHIVE도 문장을 고치지 않는다.
2. **3차에서 멈추지 않는다.** 원전까지 내려가고, 못 내려가면 못 내려갔다고 쓴다.
3. **출처 없는 인용은 싣지 않는다.** 그럴듯한 이름을 붙이는 건 최악이다.
4. **정의를 먼저, 형용사는 나중.** 감각은 정확한 단어에서 나온다.
5. **뼈대를 캐라.** 남의 은유를 빌리는 것보다 내 은유를 짓는 게 낫다.
6. **음악은 링크로.** 파일을 받지 않는다.
7. **바깥 재료로 끝내지 않는다.** 채집물은 반드시 준상이 이미 쓴 글에 착지시킨다.
8. **형식이 굳기 전에 자동화하지 않는다.**
